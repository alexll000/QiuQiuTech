# Homepage Module Mapping

这份文档用于说明：

**QiuQiuTech 首页模块，未来如何在 Directus 里配置。**

## 1. 目标

首页不应该写死在代码里。

应该把“展示什么、排第几、什么时候生效”尽量收进后台。

## 2. 首页模块清单

当前首页主模块：

1. Hero 主策划
2. 实时趋势图与事件流
3. 主案例焦点卡
4. 精选案例
5. 专题策展
6. 合作需求精选
7. 价值说明
8. 热门玩法
9. 趋势关键词
10. 用户投稿精选
11. 加入订阅

## 3. 哪些适合后台配置

### 强配置型

这些建议通过 `placements` 或独立配置项管理：

- Hero 主策划
- 主案例焦点卡
- 精选案例
- 专题策展
- 合作需求精选
- 用户投稿精选

### 半配置型

这些可以先代码固定结构，后台提供数据：

- 热门玩法
- 趋势关键词
- 实时事件流

### 先固定型

这些先不必复杂后台配置：

- 价值说明
- 加入订阅

## 4. `placements` 建议映射

### `home_hero`

控制：

- Hero 主策划主卡
- 关联一个内容 / 事件 / 专题

### `home_featured_cases`

控制：

- 精选案例三张卡

### `home_topics`

控制：

- 专题策展区

### `home_requests`

控制：

- 合作需求精选

### `home_submissions`

控制：

- 用户投稿精选

## 5. 推荐的后台字段

每个展示位记录建议包含：

- `placement_key`
- `target_type`
- `target_id`
- `sort_order`
- `start_at`
- `end_at`
- `status`
- `note`

## 6. 前台读取方式

前台首页读取策略建议：

1. 先请求首页聚合接口
2. 聚合接口从 Directus 读取相关 placement
3. 聚合后一次性返回首页渲染所需数据

不要让首页直接拼十几个 Directus 请求。

## 7. 第一阶段建议

第一阶段先做到：

- Hero
- 精选案例
- 专题策展
- 合作需求精选
- 用户投稿精选

这五块先后台可配，就已经很够用了。
