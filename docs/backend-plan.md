# Backend Plan

## 1. 后端目标

QiuQiuTech 后台不是做通用 CRUD 演示，而是要支撑这几件事：

1. 内容管理
2. 投稿审核
3. 合作需求审核
4. 专题策展
5. 展示位分发
6. 用户与认证管理
7. 抓取导入

## 2. 当前路线

### 第一阶段

- Directus 作为 CMS / Admin
- PostgreSQL 作为主库
- 本地 volume 存储文件

### 第二阶段

- 加抓取脚本与导入流程
- 前台逐步换成 Directus 数据源

### 第三阶段

- 如需要，再拆独立 API 服务
- 补搜索、推荐与更复杂流程

## 3. 第一阶段必须交付的后台能力

### 内容管理

- 正式内容列表
- 内容详情编辑
- 标签、行业、来源配置
- 上下线与发布时间

### 投稿审核

- 投稿池
- 状态流转
- 审核意见
- 发布后转为正式内容
- 草稿保存
- 投稿字段模板

### 合作审核

- 合作需求池
- 审核通过 / 驳回
- 联系方式策略
- 状态追踪
- 合作申请流转
- 申请状态留痕

### 专题管理

- 专题创建
- 专题封面
- 关联内容 / 事件 / 玩法 / 合作卡

### 展示位管理

- 首页 Hero
- 今日焦点
- 精选案例
- 合作需求精选
- 专题策展

### 用户工作台

- 用户资料扩展
- 收藏列表
- 通知中心
- 合作申请记录
- 投稿状态追踪

## 4. 抓取与导入建议

抓取不要直接写死在前台工程里。

建议目录：

```text
scripts/
├─ crawl/
├─ import/
└─ sync/
```

### 输入来源

- RSS
- 网页 URL
- 手动导入
- 后续 API 源

### 导入流程

```text
抓取原始数据
-> 数据清洗
-> 字段映射
-> 进入待审核池
-> 审核通过
-> 发布为正式内容
```

## 5. 推荐的环境分层

### 测试环境

- Directus

### 生产环境

- Directus

## 6. 接口接入顺序

### 优先级 A

1. 首页展示位
2. 内容列表
3. 内容详情
4. 专题列表
5. 专题详情

### 优先级 B

1. 合作需求列表
2. 合作详情
3. 投稿状态
4. 榜单趋势

### 优先级 C

1. 用户中心
2. Dashboard 指标
3. 抓取异常
4. 搜索
5. 提交流程 schema / 账户工作台接口

## 7. 当前前端已预留的动作接口壳层

前端已经有这些本地 API 契约：

- `/api/me/saved-items/toggle`
- `/api/me/notifications/read`
- `/api/submissions/drafts`
- `/api/requests/[slug]/apply`

后端正式接入时，优先保持这些路径语义和数据结构稳定，能减少前台返工。

## 8. 当前不做

- 复杂 IM
- 商业化结算
- 招聘系统
- 多组织体系
- 高阶推荐算法
